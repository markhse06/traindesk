# Бэкенд-сервис системы управления тренировками TrainDesk

TrainDesk — это RESTful API сервис для персональных тренеров, позволяющий управлять расписанием тренировок, клиентской базой и учетом абонементов (пакетов занятий). Сервис разработан на языке Go с использованием фреймворка Gin и ORM GORM.

## Архитектура системы

Проект спроектирован по модульному принципу с разделением зон ответственности (Clean Architecture / Domain-Driven Design elements):

* **Domain (Доменный слой):** Содержит бизнес-сущности (`User`, `Client`, `Workout`, `WorkoutPackage`, `RefreshToken`) и правила их валидации. Не зависит от внешних библиотек и фреймворков.
* **DTO (Data Transfer Objects):** Объекты авторизации и передачи данных. Разделяют внутреннее представление сущностей в базе данных и структуру JSON-ответов/запросов API.
* **App / Handlers (Транспортный слой):** Реализация REST API на базе Gin, валидация входящих запросов, управление HTTP-статусами и вызов бизнес-логики в рамках транзакций.
* **Middleware:** Слой промежуточного ПО для обеспечения безопасности (проверка JWT Access-токенов).

### Схема базы данных

Взаимодействие с PostgreSQL организовано следующим образом:

* `users` — учетные записи тренеров.
* `clients` — база клиентов, жестко привязанная к `user_id` тренера (отношение один-ко-многим).
* `workouts` — сущности тренировок. Связаны с клиентами через отношение многие-ко-многим (промежуточная таблица `workout_clients`).
* `workout_packages` — предоплаченные пакеты занятий клиентов. Сущность `Workout` может иметь необязательный внешний ключ на данную таблицу для автоматического списания сессий.

## Безопасность и авторизация

Система использует двухтокенную схему авторизации (**Access Token + Refresh Token**) с механизмом ротации (Rotation):

1. **Access Token:** Короткоживущий JWT (срок действия — 15 минут). Передается в заголовке `Authorization: Bearer <token>`. Хранит `user_id` в поле `sub`.
2. **Refresh Token:** Долгоживущий токен (срок действия — 7 дней). Представляет собой криптографически стойкую случайную строку. Хранится в базе данных. При каждом обновлении сессии старый Refresh-токен аннулируется, а клиенту выдается новая пара токенов.

## Спецификация API (API Documentation)

Все эндпоинты, кроме ветки авторизации, требуют передачи заголовка `Authorization: Bearer <ACCESS_TOKEN>`.

### 1. Модуль авторизации и управления сессиями

#### Аутентификация пользователя

* **URL:** `/api/v1/user/login`
* **Метод:** `POST`
* **Тело запроса (JSON):**
```json
{
  "email": "trainer@example.com",
  "password": "securepassword"
}

```


* **Ответ (200 OK):**
```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "8b9e6fbc...",
  "user": {
    "id": "332e0126-8598-410d-b031-b57a424e08a2",
    "email": "trainer@example.com",
    "trainer_name": "Александр"
  }
}

```



#### Обновление пары токенов (Refresh)

* **URL:** `/api/v1/user/refresh`
* **Метод:** `POST`
* **Тело запроса (JSON):**
```json
{
  "refresh_token": "8b9e6fbc..."
}

```


* **Ответ (200 OK):** Возвращает новую пару токенов, старый рефреш-токен удаляется из базы.
```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "cfa427e1..."
}

```



---

### 2. Модуль управления клиентами

#### Создание клиента

* **URL:** `/api/v1/clients`
* **Метод:** `POST`
* **Тело запроса (JSON):**
```json
{
  "first_name": "Иван",
  "last_name": "Иванов",
  "height": 180,
  "weight": 75,
  "goal": "Набор мышечной массы"
}

```


* **Ответ (201 Created):** Возвращает созданный объект клиента.

#### Получение списка клиентов

* **URL:** `/api/v1/clients`
* **Метод:** `GET`
* **Ответ (200 OK):** Возвращает массив клиентов текущего тренера со счетчиками проведенных и оставшихся (по пакетам) тренировок.
```json
[
  {
    "id": "d7d4d10b-0f66-4ef6-a3f7-93a9fd95b7e0",
    "first_name": "Иван",
    "last_name": "Иванов",
    "height": 180,
    "weight": 75,
    "goal": "Набор мышечной массы",
    "total_sessions": 12,
    "left_sessions": 4
  }
]
```



#### Частичное обновление данных клиента

* **URL:** `/api/v1/clients/:id`
* **Метод:** `PATCH`
* **Описание:** Все поля тела запроса являются необязательными. Обновляются только те поля, которые были явно переданы в JSON (благодаря механизму указателей в DTO).

### 3. Модуль управления тренировками

#### Создание тренировки

* **URL:** `/api/v1/workouts`
* **Метод:** `POST`
* **Тело запроса (JSON):**
* *Примечание:* Массив `client_ids` должен содержать как минимум один ID. Передача `package_id` автоматически спишет занятие с баланса абонемента.


```json
{
  "client_ids": ["d7d4d10b-0f66-4ef6-a3f7-93a9fd95b7e0"],
  "date_time": "2026-05-20T10:00:00+03:00",
  "duration_min": 60,
  "type": "strength",
  "notes": "Работа со свободными весами. Приседания.",
  "package_id": "4a1b2c3d-..." 
}

```


* **Ответ (201 Created):** Возвращает структуру созданной тренировки.

#### Получение списка тренировок (Расписание)

* **URL:** `/api/v1/workouts`
* **Метод:** `GET`
* **Query-параметры (Необязательные):**
* `started_at` — фильтр начала временного диапазона (формат RFC3339).
* `ended_at` — фильтр конца временного диапазона (формат RFC3339).


* **Описание:** Метод использует жадную загрузку `Preload("Clients")` для оптимизации запросов к базе данных и предотвращения уязвимости N+1.
* **Пример запроса:** `/api/v1/workouts?started_at=2026-05-01T00:00:00Z&ended_at=2026-05-31T23:59:59Z`

#### Обновление тренировки

* **URL:** `/api/v1/workouts/:id`
* **Метод:** `PUT`
* **Описание:** Поддерживает частичное обновление. Изменение массива `client_ids` выполняет атомарное обновление связей во вспомогательной таблице посредством GORM Associations внутри изолированной транзакции базы данных.

---

### 4. Модуль пакетов тренировок (Абонементы)

#### Регистрация покупки пакета

* **URL:** `/api/v1/packages`
* **Метод:** `POST`
```json
  {
    "client_id": "d7d4d10b-0f66-4ef6-a3f7-93a9fd95b7e0",
    "total_count": 10,
    "price": 15000.00
  }
```



#### Получение активных пакетов клиента

* **URL:** `/api/v1/packages/client/:client_id`
* **Метод:** `GET`
* **Описание:** Возвращает массив только активных (`is_active = true`) пакетов, у которых текущий баланс занятий не исчерпан (`used_count < total_count`). Используется мобильным приложением для наполнения выпадающего списка при создании тренировки.

## Руководство по развертыванию (Deployment Guide)

Проект подготовлен для развертывания в изолированных Docker-контейнерах под управлением Nginx в качестве Reverse Proxy.

### 1. Локальный запуск через Docker Compose

Убедитесь, что в корневом каталоге настроен файл конфигурации окружения `.env` с необходимыми переменными (`JWT_SECRET`, `POSTGRES_PASSWORD`).

Выполните команду для сборки образов и запуска контейнеров в фоновом режиме:

```bash
docker-compose up -d --build

```

### 2. Настройка Production-окружения (Ubuntu + Nginx + SSL)

1. **Настройка DNS:** Добавьте А-запись на вашем DNS-регистраторе, указывающую на публичный IP-адрес вашего VPS сервера.
2. **Получение SSL сертификата через Certbot:**
```bash
sudo apt update && sudo apt install nginx certbot python3-certbot-nginx -y
sudo certbot --nginx -d api.yourdomain.com

```


3. **Конфигурирование Nginx в режиме проксирования:**
   Отредактируйте конфигурационный файл `/etc/nginx/sites-available/default`, перенаправив входящий трафик на порт внутреннего Go-приложения (по умолчанию 8080):
```nginx
server {
    server_name api.yourdomain.com;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    listen 443 ssl;
    # Пути к SSL сертификатам Let's Encrypt добавляются утилитой certbot автоматически
}

```


4. **Проверка и перезапуск веб-сервера:**
```bash
sudo nginx -t && sudo systemctl restart nginx

```

## Логирование ошибок

В системе настроен централизованный вывод ошибок. Ответы со статусами `4xx` и `5xx` всегда возвращают стандартизированный JSON с описанием причины сбоя:

```json
{
  "error": "подробное описание ошибки для отладки клиентской части"
}

```

Все транзакции к базе данных, завершившиеся аварийно, автоматически выполняют `Rollback` для сохранения консистентности данных ACID.
